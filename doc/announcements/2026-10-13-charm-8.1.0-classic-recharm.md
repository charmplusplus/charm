Subject: Charm++ 8.1.0 is the final classic release; `main` is now `classic`; development is on `recharm` (Charm++ 9.0)

Dear Charm++ users,

Following Kale's 15 September note about Charm++ on the reconverse runtime, three changes to the
repository took effect today, 13 October 2026.

1. Charm++ 8.1.0 is the final release of the classic Converse line.
   https://github.com/charmplusplus/charm/releases/tag/v8.1.0
   It contains every bug fix since 8.0.0 plus two additions: the CkTreeCacheManager library
   (a process-shared tree-node cache with CkCache's protocol) and per-entry-method message byte
   counts in summary traces (for Projections). The full list is in the CHANGES file. Source is
   GitHub's tarball for the tag; there is no separate download site.

2. The `main` branch has been renamed `classic`. It will receive bug fixes only. If you build from a
   clone that tracks `main`, `git pull` now fails with "couldn't find remote ref main". Update the
   clone with:

       git branch -m main classic
       git fetch origin
       git branch -u origin/classic classic
       git remote set-head origin -a

   Builds pinned to a tag or a commit (for example a git submodule) are not affected. Pull requests
   that were open against `main` now target `classic`. When you open a new pull request for the
   classic line, choose `classic` as the base branch explicitly; GitHub now preselects `recharm`.

3. New development, and all future releases, are on the branch `recharm` (until today named
   `reviewed-with-reconverse`), which is now the repository's default branch. A fresh `git clone`
   gives you this branch. It builds Charm++ on the reconverse runtime and will be released as
   Charm++ 9.0. A 9.0 alpha tag will appear on the releases page in the coming days
   (https://github.com/charmplusplus/charm/releases); there will be no separate announcement for it.
   We will call it alpha until the remaining gaps below are closed. Build lines and the supported
   targets are in the manual at https://charm.readthedocs.io/en/latest/ .

   Known gaps on `recharm` today: AMPI is not yet ported; Windows multicore is not yet available;
   MPI interoperability is unsupported; the CCS server (used by liveViz, CharmDebug and PythonCCS)
   is being ported and is not in the alpha; and checkpoint files written by the alpha may not be
   readable by later 9.0 pre-releases, because the internal object-id layout may still change before
   beta (trace logs and load-balancer dumps are unaffected). Users who need any of these stay on
   `classic` for now.

Please report problems as GitHub issues at https://github.com/charmplusplus/charm/issues .

Thank you,
Ritvik Rao, for the Charm++ group
